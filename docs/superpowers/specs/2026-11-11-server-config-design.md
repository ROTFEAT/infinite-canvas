# 自托管实例的服务器配置持久化

## 已确定的目标

同一自托管实例的浏览器共享渠道、工作流和生成默认值。配置在服务器磁盘持久化，刷新、换浏览器、容器重建后可重新读取。该方案承接用户已同意的“服务器统一保存，浏览器启动读取、修改写回”。

## 方案选择

采用可选的同源配置服务和 JSON 持久卷。相较于仅发布只读默认配置，它支持网页修改；相较于重做账户/数据库系统，它适合目前一个受信任 Tailscale 实例。保留纯前端模式作为默认部署方式。

## 范围与数据

共享 AiConfig 中的渠道、工作流、模型选择和生成默认值。WebDAV 凭据、API Key、ComfyUI Proxy Token 仍留在各浏览器，不写入共享文件。画布项目、生成历史、素材和模型文件不属于此功能。主题/语言也不共享。禁止把实际服务器配置或凭据提交到 GitHub。

## 数据流

- 显式启用服务器模式后，先等待浏览器 store hydration，再 GET /api/instance-config。成功才显示应用；读取失败显示重试，不静默使用旧配置。
- 空服务器不自动接收浏览器默认值：显示“使用当前浏览器配置初始化”，用户点击后写入第 1 版。
- 已有服务器配置覆盖同一实例的本地非凭据配置，按渠道 ID 保留本地凭据。
- 后续配置变动经过短暂 debounce 串行 PUT。请求带 baseRevision，服务端版本不匹配返回 409，禁止无声覆盖另一浏览器更新。
- 冲突/失败显示状态和“重试保存”“读取服务器配置”操作。重试沿用原 revision，不能绕过冲突。读回覆盖前提醒本地未保存修改会被替换。
- 其他已打开的浏览器通过刷新获取最新设置；首版不做实时推送。

## 持久化与边界

Node 内置 HTTP/fs 实现小型服务，不新增数据库。所有读改写串行化，写临时文件后原子 rename；JSON 文件 0600。重启后从磁盘读取。坏文件拒绝读取/覆盖，不当作空配置。请求上限 5 MiB，固定路径，不接受客户端文件路径。

服务仅供受信任的单实例成员使用，所有有该实例访问权限的成员共享配置写权限。独立服务默认监听 loopback；Compose 不发布服务端口，经画布 Nginx 同源代理访问。写请求要求 JSON、自定义头和同源 Origin；不开放 CORS。公网部署必须由运营者在反向代理提供认证；此功能不提供账户、租户或权限系统。

## 验收

HTTP 集成测试验证重启恢复、并发版本冲突、原子写入、坏文件保护、无凭据共享、错误请求和跨源写入拒绝。客户端测试验证初始化不自动写、修改串行保存、冲突停止、读失败不覆盖、本地凭据保留及纯前端模式不请求服务。当前线上 H3 环境不随开发分支自动升级。

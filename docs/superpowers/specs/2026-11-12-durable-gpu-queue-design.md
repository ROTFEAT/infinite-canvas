# 双 GPU 持久化生成队列

用户已确认“统一队列 + 两个 ComfyUI 实例、每张卡一个消费者”的方案并要求实现。

## 范围

保留现有 20 步 H3 工作流和画布交互。可选同源 `/api/generation` 服务兼容当前浏览器使用的 ComfyUI prompt/queue/history/upload/view/object_info/system_stats/WebSocket 接口；默认静态部署仍可直连。部署时将 H3 渠道地址切换为该入口。

SQLite 持久化提交的完整工作流、任务状态、分配到的 worker、输出历史和错误。两个固定配置的 worker 各绑定一张 GPU，一次最多接受一个队列任务；外部直接提交的任务也占用该 worker。任务先落盘再返回成功。禁止浏览器提供上游 URL。

任务状态：queued → dispatching → running → succeeded/failed/interrupted/cancelled。派发前记录固定 UUID，ComfyUI 支持客户端指定 prompt_id。断线或服务重启先查询 worker 的 queue/history；无法确定是否已接收时不重复提交，保持核对状态；确认丢失时显示 interrupted，可手动重试（新 ID，保留原记录）。不承诺进程崩溃后的采样断点恢复。

新任务页面显示所有服务端任务的排队、GPU 分配、节点进度、错误和结果链接；失败或中断可重试，取消精确到任务，不中断另一张卡。浏览器关闭不终止已提交任务，回来后可从任务页面取结果。画布本身仍是浏览器本地数据，不声称跨浏览器同步画布。

上传输入目录由两个实例共享。输出目录独立，网关按 worker 路由结果，避免同名文件冲突。仅信任 Tailscale 内用户；写请求校验 Origin，大小受限，SQLite 和素材位于持久存储，worker 地址是服务端白名单。

## 资源与验证

现有单实例约占 41GB 主机内存，虚拟机约 53GB。采用减少缓存/关闭锁页内存等可回滚参数并实测，不能直接复制两个现状进程。两个 GPU 同时跑 20 步 H3 验证峰值内存和完成结果；不改画质设置换取通过。发现内存不足则调整缓存，必要时明确报告实际并发限制。

覆盖排队、两 worker 并发、worker 离线、调度服务重启、结果持久化、提交响应丢失、取消与重试、输入上传和输出路由；部署前保留 compose/配置备份。默认部署不启用该服务。
